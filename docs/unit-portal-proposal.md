# ร่างเว็บเฉพาะหน่วย — Kelang Health Performance

วันที่ตรวจแหล่งข้อมูล: 6 ตุลาคม 2569
สถานะ: ข้อเสนอและต้นแบบ ไม่แก้เว็บที่เผยแพร่ ไม่เพิ่มตาราง และไม่เปลี่ยนข้อมูลจริง
ต้นแบบ: docs/unit-portal-design.html

## แนวทางที่เสนอ

ใช้เว็บไซต์เดียวและแม่แบบเดียวสำหรับทั้ง 8 หน่วย เลือกด้วย facility_code ในเส้นทาง เช่น #unit/06117/home แบ่งเป็นหน้าประชาชน หน้าแสดงผลงาน และพื้นที่เจ้าหน้าที่ที่ตรวจสิทธิ์ก่อนอ่านข้อมูล หน่วยที่ไม่มีข้อมูลหรือไม่ได้เปิดบริการนั้นให้ซ่อนรายการ ไม่ใส่ตัวเลข/วันบริการที่อนุมาน

หน้าแรกองค์กรยังใช้เปรียบเทียบทั้ง 8 หน่วยได้ กดชื่อหรือการ์ดหน่วยแล้วเข้าสู่หน้าเฉพาะหน่วย ลิงก์แต่ละหน่วยแชร์หรือสร้าง QR ได้โดยใช้รหัสหน่วย ไม่ต้องแยกโดเมนหรือทำเว็บ 8 ชุดบนระยะแรก

## หลักฐานที่ใช้ประกอบการออกแบบ

1. [คู่มือมาตรฐานหน่วยบริการปฐมภูมิ พ.ศ.2568–2570 — แหล่งเผยแพร่กลุ่มงานปฐมภูมิและเครือข่ายสุขภาพ กระทรวงสาธารณสุข](https://divisionksn.moph.go.th/sam/?p=440): ใช้ประกอบการวางหมวดข้อมูลด้านการบริหาร บุคลากร สถานที่ สารสนเทศ และระบบบริการ รวมถึงการสื่อสารข้อมูลบริการ/ผู้รับผิดชอบ การแบ่งหน้าเว็บนี้เป็นข้อเสนอ ไม่ใช่เกณฑ์รับรองว่าเว็บไซต์ผ่านมาตรฐาน
2. [แผนผังเว็บ ศูนย์บริการสาธารณสุข 68 สะพานสูง สำนักอนามัย กทม.](https://webportal.bangkok.go.th/healthcenter68/sitemap): มีข้อมูลทั่วไป โครงสร้าง ตารางบริการ ปฏิทินกิจกรรม ข่าว ติดต่อ และคู่มือประชาชน จึงเสนอให้หน้าเฉพาะหน่วยเริ่มจากข้อมูลที่ประชาชนค้นหาและใช้งานได้
3. [ตัวอย่างตารางบริการ ศูนย์บริการสาธารณสุข 54 ทัศน์เอี่ยม](https://webportal.bangkok.go.th/healthcenter54/page/sub/9243/ตารางการให้บริการ): แยกวัน/ช่วงเวลา/คลินิก เป็นตัวอย่างโครงสร้างตารางเท่านั้น ไม่ยกตารางเวลาหรือประเภทบริการของ กทม. มาอ้างว่าหน่วยเขลางค์นครให้บริการแบบเดียวกัน
4. [ศูนย์รวมแบบฟอร์ม รพ.สต. อบจ.ลำปาง](https://health.lp-pao.go.th/doph_system/main/pages/hph_report_form.php): พบรายงาน OPD/ER/Refer, Telemedicine และงานเภสัชกรรม จึงเสนอเป็นโมดูลเสริมหลังยืนยันว่ามีบริการจริง นิยามข้อมูลชัดเจน และแหล่งรายงานพร้อม
5. [ภารกิจกองสาธารณสุขและสิ่งแวดล้อม เทศบาลเมืองเขลางค์นคร](https://www.kelangnakorn.go.th/kelang/?p=158): ประกอบบริบทการส่งเสริมสุขภาพ ป้องกันและควบคุมโรค และงานกองทุน ไม่คัดลอกชื่อผู้ดำรงตำแหน่งจากหน้าเว็บมาเติมโดยไม่มีการยืนยันจาก ADMIN

## การแยกข้อมูลเฉพาะหน่วย

facility_code เป็นตัวกรองหลักในทุกการอ่านและเขียน รวมถึงการเปิดลิงก์ตรง ไม่ใช้ชื่อหน่วยเป็นรหัส การแสดงหน้า public ต้องอ่านเฉพาะ published=true ของหน่วยนั้น การเปิดหน้าเจ้าหน้าที่หน่วยอื่นด้วยการแก้ URL ต้องถูกปฏิเสธฝั่งฐานข้อมูล ไม่พึ่งเพียงซ่อนปุ่ม

ข้อมูลเปิด: บริการ ตารางคลินิก ติดต่อ รายชื่อที่อนุมัติ ข่าว/ภาพกิจกรรมที่อนุมัติ และสถิติรวมที่กำหนดให้เผยแพร่
ข้อมูลสำหรับผู้บริหาร: แดชบอร์ดที่เลือกเปิดเผยได้ กับรายงานภายในที่ต้องเข้าสู่ระบบ; การเลือกซ่อนข้อมูลภายในต้องควบคุม API/RLS จริงด้วย
ข้อมูลไม่รวมในโครงการร่างนี้: เวชระเบียนรายคน รายชื่อผู้ป่วย นัดหมายรายบุคคล เลขบัตร ที่อยู่รายบ้าน บัญชีเงินเดือน และข้อมูลจาก compensation ที่ไม่เกี่ยวกับบุคลากรสาธารณะ

ADMIN: ข้อมูลทุกหน่วย/อนุมัติ/กำหนดสิทธิ์
STAFF: ร่างและแก้ข้อมูลเฉพาะหน่วยที่ได้รับสิทธิ์ ส่งตรวจ และเปลี่ยนรูปหน่วยตนเอง
USER: เปลี่ยนรูปตนเองตามการเชื่อมบัญชีเดิม ไม่ได้รับสิทธิ์เผยแพร่เนื้อหาหน่วย
ประชาชน: อ่านเฉพาะข้อมูลเปิดของหน่วย

วงจรข้อมูลใหม่: ร่าง → ส่งตรวจ → เผยแพร่ → หมดอายุ/พักแสดง โดยมีผู้ตรวจและวันทบทวน กำหนดประกาศเปลี่ยนคลินิกให้แสดงเหนือปฏิทิน เมื่อมีข้อมูลขัดกันให้พักข้อความเดิมจนตรวจสอบ

## ใช้ของเดิมและสิ่งที่จะเพิ่ม

ใช้เดิม: hp_facilities/hp_facility_profiles, hp_population, hp_personnel, hp_volunteers, hp_budget_monthly, hp_finance_monthly, hp_ncd_monthly, hp_cd_monthly, hp_service_stats, hp_user_facilities, hp_audit_logs และ KPI HDC เดิม ไม่คัดลอกชุด HDC หรือภาพบุคลากรเพิ่มอีกชุด

ระยะเริ่มต้นเสนอเพิ่ม 2 ตาราง (ยังไม่สร้างจริง):
- hp_unit_services: facility_code, service_key, title, service_description, preparation, eligibility_note, contact_channel, weekly_sessions (JSON), effective_from, effective_until, publication_status, reviewed_by, reviewed_at, updated_at. สัปดาห์หนึ่งมีหลายช่วงเวลาได้ กำหนดข้อยกเว้นวันหยุดเป็นประกาศแยก มี unique facility_code+service_key; RLS ตามหน่วยและสถานะ
- hp_unit_content: facility_code, content_type (news/event/document/faq/notice), title, plain_text, event_start/end, external_url, status, publish_from/until, reviewed_by, reviewed_at, updated_at. ช่วงแรกใช้ข้อความธรรมดาและลิงก์ที่ตรวจ scheme และแหล่งที่มา ไม่เปิด HTML จากผู้ใช้ ภาพกิจกรรม/ข้อยกเว้นตารางค่อยเพิ่มภายหลัง

เพิ่มช่องติดต่อ/พิกัดที่ยืนยัน/วันทบทวนใน hp_facility_profiles ด้วย migration เมื่อเริ่มทำจริง ไม่ใช้ raw_data ที่มีข้อมูลนำเข้าปะปนเป็นข้อมูลเว็บสาธารณะ กำหนดรายการช่องที่อนุญาตให้เผยแพร่ชัดเจน

## ระยะพัฒนา

1. ทดลอง 1 หน่วย: หน้าพื้นฐาน ติดต่อ ตารางบริการ บุคลากร และผล HDC หน่วยเดียว; ยืนยันข้อมูลจากหน่วยก่อนเปิดจริง
2. ขยายทั้ง 8 หน่วย: ร่าง–ตรวจ–เผยแพร่ สิทธิ์แก้เฉพาะหน่วย ข่าว/FAQ/คู่มือ และลิงก์แชร์
3. เพิ่มตามแหล่งข้อมูลจริง: OPD/ส่งต่อ/Telemedicine/เภสัชกรรม แผนที่ชุมชน รายงานคุณภาพและงานกองทุน ไม่เพิ่มโมดูลที่ไม่มีผู้ดูแลหรือแหล่งข้อมูลพร้อม

## พื้นที่และการดูแล

เริ่มจากข้อความและลิงก์เอกสารต้นทาง ไม่เก็บ PDF ซ้ำ รูปบุคลากรใช้ข้อจำกัดเดิม 100 KB/คน ถ้าเพิ่มภาพสถานที่/กิจกรรม เสนอไม่เกิน 200 KB/ภาพ และจำกัดจำนวนพร้อมการลบไฟล์เก่าจริง จำกัดแกลเลอรีเริ่มต้นไม่เกิน 5 ภาพ/หน่วย รวมสูงสุดประมาณ 7.81 MiB สำหรับ 8 หน่วย (เป็นเพดานข้อเสนอ ไม่ใช่การใช้พื้นที่จริง และยังไม่เพิ่ม bucket)

ระบบใช้ฟรีต้องประเมินพื้นที่ทั้งหมดและการรับส่งข้อมูลของโครงการจริง การย่อภาพลดพื้นที่ได้ แต่ไม่รับประกันว่า free plan จะเพียงพอกับแอปอื่นในโครงการเดียวกัน

## ข้อมูลที่ต้องยืนยันก่อนนำต้นแบบขึ้นจริง

ต่อหน่วย: ชื่อทางการ/ประเภทหน่วย, โทรศัพท์และช่องทางหน่วย, ที่อยู่/พิกัด, เวลาทำการและวันหยุด, รายการบริการและตารางคลินิก, หัวหน้าหน่วย/ทีมที่อนุญาตเผยแพร่, ชุมชนรับผิดชอบและปีอ้างอิง, เครือข่ายส่งต่อที่ใช้งานจริง, ผู้รับผิดชอบการทบทวนและผู้อนุมัติ

ต้นแบบใช้ชื่อ/รหัสจากทะเบียนในระบบเท่านั้น ตัวเลขผลงาน ตารางเวลา ติดต่อ และผู้รับผิดชอบที่ยังไม่ยืนยันแสดงเป็นช่องรอข้อมูล ไม่คัดลอกข้อมูลบริการของหน่วยอื่นมาเป็นข้อมูลจริงของเขลางค์นคร
