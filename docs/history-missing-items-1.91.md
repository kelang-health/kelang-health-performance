# เพิ่มรายการรายจ่ายย้อนหลังและยืนยันล็อกข้อมูล — 1.91

20 ตุลาคม 2569

- หน้า `#spending` ปี 2568–2569 ให้ผู้มีสิทธิ์หน่วยแก้ชื่อรายการ ยอดจ่าย และเพิ่มรายการที่ตกหล่นใน 11 หมวดเดิมได้ เก็บรายการต้นฉบับและแหล่งที่มาไว้ ห้ามลบ/ย้ายรายการเดิมผ่าน API
- “บันทึก” เก็บร่างเพื่อแก้ต่อ “ยืนยันบันทึก” ตรวจข้อมูลและช่วงเวลาแล้วล็อกทั้งยอด ชื่อ และรายการใหม่ ADMIN ต้องเปิดแก้พร้อมเหตุผลก่อน STAFF บันทึกต่อได้
- ไม่เพิ่มตาราง ไม่เปลี่ยนบทบาทบัญชี ใช้ RLS รายหน่วยและ audit เดิม ยืนยันแล้วแม้ ADMIN ต้องเปิดแก้เป็นขั้นตอนแยกก่อน
- รายการใหม่มี ID คงที่ ป้องกันรหัสซ้ำ ชื่อว่าง ยอดผิด และจำนวนเกิน 250 รายการต่อหมวด ช่องเพิ่มรายการที่ยังไม่กดเพิ่มจะถูกเก็บในร่างหน้าจอ พร้อมเตือนก่อนบันทึก/เปลี่ยนหน้า ไม่หายเมื่อเกิดข้อผิดพลาด
- รวมยอดเมื่อรายละเอียดครบและยอดหมวดเดิมอิงรายละเอียดชุดนั้น หากยอดหมวดเดิมเป็นหลักฐานรวมที่ยังแจกแจงไม่ครบ จะคงยอดเดิมและแสดงส่วนต่างให้ตรวจ ไม่แทนด้วยยอดรายการใหม่เพียงรายการเดียว
- ปี 2567 คงข้อกำหนดโครงสร้างเดิม ปี 2570 ยังคงบันทึกรายเดือนแยกตารางตามเดิม

ผลทดสอบ: 179 unit tests และ build ผ่าน UI จำลอง REST ครบ STAFF/ADMIN/MONITOR/อ่านอย่างเดียว/USER/ไม่เข้าสู่ระบบ รวมเพิ่มรายการ แก้ชื่อ บันทึก โหลดกลับ ยืนยัน ล็อกข้อมูล เปลี่ยนปี/หน้า ข้อมูลค้าง และมือถือ 390/768/1440px ผ่าน พร้อมทดสอบรายเดือนและหน้าการเงินปี 2570 ผ่าน

Cloud ทดสอบใน transaction แล้ว ROLLBACK: เพิ่มและแก้ชื่อรายการปี 2568 และ 2569 บันทึกร่าง/ยืนยัน ปิดการแก้ข้ามหน่วย ปิดแก้หลังยืนยัน ปิด STAFF ปลดล็อก อนุญาต ADMIN ปลดล็อกแล้ว STAFF แก้ต่อ ป้องกันแก้ต้นฉบับ/ลบรายการเดิม/รหัสปลอม และตรวจ audit ผ่าน ทั้งชุดทดสอบเดิม `spending_history.sql` และชุดใหม่ `history_missing_items.sql`

ตรวจ security advisors ไม่พบข้อสังเกตใหม่เกี่ยวกับฟังก์ชัน/ตารางประวัติ ข้อมูลจริง 24 ชุดและแผนปี 2570 checksum ตรงกับก่อนงาน ไม่มีข้อมูลทดสอบค้างใน Cloud
