# ตรวจ HDC API — Ver.1.2

ตรวจ 6 ตุลาคม 2569 จาก Swagger ของ https://opendata.moph.go.th/api/document/ และ https://api-hdc.moph.go.th/api-docs/ โดยอ่าน swagger-ui-init.js ของแต่ละเว็บไซต์

คำขอ POST /api/report_data ด้วย s_aged9, year 2569, province 52, type json สำเร็จ HTTP 201 มี 996 แถว ค่า CORS Access-Control-Allow-Origin เป็น * และเรียกจากเบราว์เซอร์ที่เปิด GitHub Pages ได้จริง ไม่มีความจำเป็นต้องใช้ jQuery ในระบบใหม่

Swagger ระบุ limit default 1000 สูงสุด 10000 และ offset default 0 ระบบกำหนด limit 10000 พร้อม pagination เพื่อไม่ตัดข้อมูลรายงานขนาดใหญ่

ตรวจหน้า AREA บนเว็บจริง ปี 2569 เลือก S_AGED9 แสดงผลงานรวม 13,410 / 15,143 = 88.6% ครบ 7 หน่วย ข้อมูลถึง 5 ตุลาคม 2569 เวลา 10:41 ดังนั้น KPI นี้ไม่ได้หายทั้งหมดจากหน้าเว็บ

สาเหตุที่เห็นไม่สด/ว่างในบางมุมมอง:

- ระบบเดิมใช้ scheduled snapshot ปุ่มรีเฟรชอ่าน snapshot ซ้ำ ไม่ได้เรียก API สด
- การดึง 26 KPI หลายปีอย่างถี่จาก runner เคยได้รับ HTTP 429 ข้อมูลล่าสุดที่มีถูกเก็บพร้อม stale/error
- s_aged9 มี target/result สะสมรายปี ไม่มี field รายเดือนที่ตรวจยืนยัน จึงไม่สร้างกราฟรายเดือนจากยอดปี
- ปี 2570 บาง dataset ยังไม่มีข้อมูล ต้องแยก “ไม่มีข้อมูล” จากศูนย์จริง

แก้ไข: เพิ่มปุ่มดึง API สดเฉพาะ KPI ที่เลือก, รักษา cache สำเร็จล่าสุดหลัง reload, แสดงผลการเชื่อมต่อในหน้า, ลด sync เป็นทีละ endpoint ห่าง 3 วินาที, โหลดข้อมูลที่เผยแพร่ล่าสุดก่อน sync และคำนวณ summary จาก fallback ที่ใช้จริง เมื่อ API ทั้งหมดขัดข้องแต่มีข้อมูลจริงเดิมจะยังเผยแพร่การแก้หน้าเว็บพร้อมสถานะ stale ได้ การ push เพื่อปรับ UI จะใช้ข้อมูลที่เผยแพร่ล่าสุดโดยไม่ยิง API ทุกชุดซ้ำ ส่วน schedule รายวันและ manual workflow ยัง refresh API ตามปกติ
