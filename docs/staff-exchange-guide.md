# รับส่งข้อมูลเจ้าหน้าที่ cloud–local รุ่น 1.77

ปรับปรุง 12 ตุลาคม 2569 · Apiwat Meethong

## เมนู

- cloud: ระบบเจ้าหน้าที่ → เลือกบุคลากรและปี → การลาและวันทำการ → **รับส่งเจ้าหน้าที่ / ฉ.11 / รูป**
- local: เมนูงานเจ้าหน้าที่ → **ข้อมูลเจ้าหน้าที่ / ฉ.11 รับส่ง** (`staff_exchange.php`)
- เมนู **ทะเบียนลา / ปฏิทินรายหน่วยรับส่ง** ยังคงใช้เลือกวันลา ปฏิทิน และสิทธิเป็นรายรายการได้

## ข้อมูลที่รองรับ

| ข้อมูล | ส่งออก | รับเข้า local | รับเข้า cloud |
|---|---|---|---|
| ชื่อเต็ม ตำแหน่ง ระดับตำแหน่ง ประเภทบุคลากร | ได้ | ปรับตำแหน่ง/ระดับในทะเบียนเดิม ชื่อที่ต่างต้องแก้ส่วนชื่อในทะเบียนก่อน | ปรับทะเบียนตามสิทธิ์หน่วย |
| ฉ.11 ประจำปี/รายเดือนและช่องประกอบ ประวัติงานในแบบ | ได้ สูงสุด 13 ใบ/คน/ปี | เปิดแก้ร่างและพิมพ์ผ่านหน้าใหม่ | รับเป็นร่าง ข้ามเอกสารที่ยืนยันหรือมีฉบับยืนยันย้อนหลัง |
| รูปบุคลากรจริง | WebP ไม่เกิน 100 KB ไม่ใช่ลิงก์หมดอายุ | เก็บในฐาน local เปิดดูได้ | ใช้ Storage และสิทธิ์อัปโหลดเดิม |
| วันหยุด วันทำการ สิทธิวันลา ทะเบียนลา | ได้ | ใช้ระบบปฏิทินรายหน่วย/ทะเบียนลาเดิม | ใช้ RPC ที่ตรวจหน่วยและรุ่นข้อมูล |

แฟ้มไม่เกิน 2 MB **ต่อคนต่อปี** เข้ารหัส AES-256-GCM/PBKDF2 รหัสผ่าน 12–256 ตัวอักษร ไม่มีการซิงค์อัตโนมัติ รูปที่อัปโหลดตามระบบเดิมรับต้นฉบับไม่เกิน 2 MB แล้วย่อเก็บไม่เกิน 100 KB

ไม่ได้ใช้แฟ้มนี้แทนการสำรองฐานข้อมูลทั้งระบบ ไม่ขนบัญชี รหัสผ่าน สิทธิ์ผู้ใช้ หรือผลลงนามไปอนุมัติที่ปลายทาง ประวัติฉบับยืนยันราชการยังอยู่ที่ระบบต้นทาง

## ขั้นตอน

1. ผู้เขียนติดตั้งชุด local ของหน่วยนั้นด้วย CLI และ ADMIN ตรวจเชื่อม UUID บุคลากรในเมนูรับส่งทะเบียนลา ห้ามจับคู่จากชื่อโดยอัตโนมัติ
2. ADMIN cloud ลงทะเบียน `local:<instance>` ของหน่วยนั้นในเมนูรับส่งทะเบียนลา ชุดที่ติดตั้งครั้งนี้อนุญาตหน่วย **06116** เท่านั้น
3. เลือกคนและปีให้ตรงกัน → ส่งออกครบชุด → เก็บรหัสผ่านแยกจากแฟ้ม
4. ปลายทางเลือกคนและปีเดิม → ตรวจแฟ้ม → เปิดดูข้อมูลก่อน/หลัง → เลือกส่วนที่จะรับเอง ไม่มีการเลือกอัตโนมัติ
5. ยืนยันหลังตรวจ ระบบดาวน์โหลดแฟ้มสำรองเข้ารหัสของข้อมูลปลายทางก่อนเริ่มบันทึก เก็บแฟ้มสำรองนี้ไว้ด้วย
6. อ่านผลทีละส่วน: ชื่อ/ตำแหน่ง, เอกสาร, รูป, ทะเบียนลา แต่ละส่วนบันทึกแยกกัน หากผิดพลาดจะหยุดและแจ้งส่วนที่สำเร็จแล้ว ตรวจแฟ้มใหม่เพื่อทำต่อ
7. ทะเบียนลาที่ขัดแย้งให้ใช้เมนูทะเบียนลาเพื่อเลือกเป็นรายรายการ เมนูนี้อ่านแฟ้มครบชุดได้ แต่แสดงชัดว่าไม่รับชื่อ/รูป/ฉ.11
8. ตรวจปฏิทินและรายการลาจริงก่อนคำนวณประกอบ ฉ.11 ใบรับรองที่รับเข้ามาจะไม่ถือว่ายืนยันวันทำงานแล้ว การอนุมัติราชการยังต้องลงนามจริง

ชื่อเต็ม cloud และชื่อแยกใน local อาจจัดเก็บต่างกัน หากชื่อไม่ตรงจะไม่แยกชื่อ/นามสกุลโดยเดา ให้ STAFF ตรวจแก้ทะเบียนบุคลากรเดิมก่อนรับส่วนชื่อ/ตำแหน่ง รูปที่ต้นทางไม่มีจะไม่ลบรูปเดิม

## local และแบบพิมพ์

ชุดติดตั้งเพิ่มตาราง local เพียง `compensation_staff_exchange` ใช้ JSON จำกัดขนาดร่วมกับทะเบียน/ตารางแลกเปลี่ยนเดิม ไม่เพิ่มตารางบน Supabase

เอกสารที่รับเข้าหรือแก้ผ่านหน้าใหม่อยู่ในตารางนี้ ไม่เขียนทับ `compensation_records` เดิม เปิดแก้และพิมพ์ที่ **ข้อมูลเจ้าหน้าที่ / ฉ.11 รับส่ง** เอกสารเดิมที่จับคู่รหัสบุคลากรหรือชื่อเต็มตรงและไม่ซ้ำสามารถแสดง/ส่งออกผ่านสะพานข้อมูลได้ ช่องที่ไม่มีในข้อมูลเดิมจะเว้นไว้ ไม่เดาอัตรา วันที่ หรือผลลงนาม

ใช้ตัวจัดพิมพ์ที่ตรึงไว้ `src/staff/renderers/1.74` พร้อมฟอนต์และต้นฉบับแบบราชการเดียวกับ cloud ไม่เปลี่ยนข้อความหรือแบบต้นฉบับ พื้นที่สะพานข้อมูล local จำกัด 25 MB ต่อชุดติดตั้ง

## ผลตรวจครั้งนี้

- JavaScript 147 tests ผ่าน
- local MySQL 37 checks ผ่านในฐานทดสอบแยก รวมรูปจริง ร่าง ฉ.11 รุ่นข้อมูล และ rollback เมื่อเอกสารท้ายชุดผิด
- cloud 6 checks ของบุคลากร/ฉ.11 และ 21 checks ระบบรับส่งทะเบียนลา ผ่านโดย rollback ทั้งหมด
- Browser ครบชุด 8 flows ผ่าน และทะเบียนลาเดิม 8 flows ผ่าน
- หน้า local จริงแสดง ฉ.11 อภิวัฒน์ 2 ใบ ดูตัวอย่างรายเดือนและประจำปีได้ ฟอนต์และภาพแบบราชการโหลดครบ
- ทดลองรับข้อมูลจริงเฉพาะ ฉ.11 ของอภิวัฒน์ ปี 2570 จำนวน 2 ใบ เป็นร่างใน local สำรองก่อนนำเข้าเข้ารหัสไว้นอกเว็บ ไม่มีการย้ายรูปหรือวันลาจริงในการทดลองนี้
- Security advisors ไม่มีรายการใหม่ ยังคง 29 INFO และ 1 WARN เดิมของ `hp_touch_session`

ขั้นถัดไป: ตรวจร่างอภิวัฒน์และวันทำงานจริงเดือนตุลาคมก่อนลงนาม แล้วให้ผู้เขียนติดตั้ง/ลงทะเบียน/เชื่อม UUID ของหน่วยอื่นทีละหน่วย และทดลองรับส่งก่อนใช้งานจริง
