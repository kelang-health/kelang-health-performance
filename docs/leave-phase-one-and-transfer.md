# ระบบลาและวันทำการ — เฟส 1 รุ่น 1.75

ใช้ความสามารถจาก compensation/work_leave.php, work_calendar.php, workday_lib.php และแบบพิมพ์ leave_print.php/leave_print_approval.php ไม่เปลี่ยนฐาน local และไม่มีการซิงค์

## เปิดใช้งานเฟสแรก

- หน้าสำหรับเจ้าหน้าที่ เลือกปีงบประมาณและบุคลากร แล้วใช้ส่วนการลาและวันทำการด้านล่าง
- USER ที่เชื่อมบุคลากรสร้าง/แก้คำขอรอผลและยกเลิกคำขอรอผลของตนเองได้
- STAFF จัดการเฉพาะหน่วยตนเอง รวมปฏิทิน สิทธิรายปี และบันทึกผลตามเอกสารอนุมัติ ตามที่ผู้ใช้ยืนยัน
- ADMIN จัดการได้ทุกหน่วย การบันทึกผลในโปรแกรมไม่แทนผู้มีอำนาจอนุมัติตามราชการ ต้องมีชื่อผู้อนุมัติจริง วันที่ และเอกสารอ้างอิง
- ประเภท SICK, PERSONAL, VACATION, MATERNITY, ORDINATION, OFFICIAL, OTHER ใช้รหัสจาก local เดิม; แบบพิมพ์เปิดเฉพาะป่วย/กิจ/คลอด/พักผ่อนที่มีต้นแบบอยู่แล้ว ประเภทอื่นเก็บทะเบียนได้ แต่ไม่สร้างแบบราชการขึ้นเอง
- ปฏิทินเริ่มจากเสาร์อาทิตย์เป็นวันหยุด เก็บเฉพาะวันที่แก้จากค่าเริ่มต้น/วันที่มีหมายเหตุใน JSON รายเดือน ไม่ใช้ตารางหนึ่งแถวต่อวัน ต้องตรวจวันหยุดตามประกาศของหน่วยงานเอง
- แก้ปฏิทินจะกลับเป็นร่าง ต้องยืนยันอีกครั้ง การยืนยันจาก local ไม่ยกมาเป็นการยืนยันของ cloud อัตโนมัติ
- วันลาเต็มวันนับเฉพาะวันทำการ ครึ่งวันใช้ได้วันเดียว และยังกันช่วงลาซ้อนกันทั้งเช้า/บ่ายในวันเดียวตามระบบเดิม
- โควตากรอกตามเอกสาร ไม่คาดเดาจากประเภทบุคลากร ช่องว่างคือยังไม่กำหนด ต่างจากศูนย์ คงเหลือติดลบแสดงจริงเพื่อให้ตรวจ ไม่ปัดให้เป็นศูนย์
- ฉ.11 มีปุ่มเติมตัวเลขเบื้องต้น ต้องยืนยันปฏิทินและตรวจว่าทะเบียนครบก่อน รายการรอผลจะขัดขวางการคำนวณ มีไปราชการ/หยุดอื่นต้องตรวจวันปฏิบัติงานเอง ไม่มีการยืนยันวันทำงานจริงหรือเปลี่ยนฉบับที่ยืนยันแล้วอัตโนมัติ
- ชื่อบนคำขอเก็บจากทะเบียนบุคลากรโดยฐานข้อมูล พร้อม revision และประวัติผู้บันทึกล่าสุดไม่เกิน 50 เหตุการณ์ รายการสิ้นสุดห้ามแก้ ไม่มีสิทธิ์ลบจริง ใช้สถานะยกเลิก

เพิ่ม 3 ตาราง: hp_leave_requests, hp_work_calendars, hp_leave_entitlements; ใช้ทะเบียนบุคลากรและบัญชีเดิม ไม่มีตารางประเภทลา/รายวัน/ประวัติแยกซ้ำ และไม่พึ่งคุณสมบัติ Pro

นำปฏิทิน local ปี 2570 จำนวน 12 เดือนมาวางเป็นร่างเฉพาะหน่วย 06116 ไม่ทับปฏิทิน cloud ที่มีอยู่ ไม่ย้ายประวัติลา/โควตา/บัญชีผู้ใช้เดิมอัตโนมัติ

## ขอบเขตเฟสถัดไป: ส่งออกและนำเข้าด้วยไฟล์

ส่วนนี้เป็นแบบออกแบบ ยังไม่มีปุ่มส่งออก/นำเข้าที่เปิดให้ใช้ในเฟสแรก

1. ผู้เขียน/ADMIN ลงทะเบียนชุด local แต่ละชุดด้วย installation_id ถาวรและ facility_code ที่อนุญาต บัญชี STAFF ยังต้องผ่านสิทธิ์หน่วยใน cloud ไม่เชื่อสิทธิ์ที่ระบุมาเองในไฟล์ ชุด local ของหน่วยอื่นไม่ยกระดับสิทธิ์ข้ามหน่วย
2. เลือกหน่วย ปี/เดือน และชุดข้อมูลก่อนส่งออก: บุคลากรเท่าที่จำเป็น, ทะเบียนลา, ปฏิทิน, โควตา; ไม่มีรหัสผ่าน/session/token/service key หรือข้อมูลผู้ป่วย
3. แฟ้มเข้ารหัสมี manifest: format=kelang-leave-transfer, schema_version=1, package_id UUID, source_instance, target_facility, exported_at, period, record counts และ SHA-256 ของแต่ละส่วน ค่า checksum ตรวจความเสียหาย ไม่ใช่หลักฐานผู้ส่ง; ผู้รับตรวจสิทธิ์และผู้ส่งแยกอีกชั้น
4. ทุกรายการใช้ UUID ถาวร id ร่วมกับ origin_instance/source_key และ revision ที่มีในเฟสแรก เลข AUTO_INCREMENT local ไม่ใช้เป็นรหัสกลาง เพิ่ม mapping ที่ local สำหรับ UUID และบุคลากร ไม่จับคู่ด้วยชื่อหรืออีเมลล้วน ๆ ไม่ใช้เลขบัตรประชาชนเป็นรหัสแลกเปลี่ยน
5. นำเข้าเป็นสองขั้น: ตรวจไฟล์/ขอบเขต/รุ่น/อ้างอิง/วันลาซ้อน/ไฟล์ซ้ำ แล้วแสดงผลทดลองว่าเพิ่ม แก้ ขัดแย้ง หรือข้าม ให้ผู้รับตรวจรายการจริงก่อนนำเข้าใน transaction เดียว สำรองก่อนเปลี่ยนข้อมูล
6. ตรวจ package_id และ record UUID + fingerprint เพื่อให้ไฟล์เดิมนำเข้าซ้ำแล้วไม่เกิดรายการซ้ำ หากปลายทางถูกแก้หลังส่งออกให้เป็น conflict ไม่ใช้หลักว่าเวลาใหม่กว่าทับเสมอ ผู้รับต้องเทียบและเลือกรายการเป็นกรณีไป
7. วันที่ยืนยัน/ผู้บันทึกจากต้นทางเก็บเป็น provenance ไม่อ้างว่าเป็นผู้อนุมัติใน cloud ปฏิทินที่นำเข้ากลับเป็นร่าง และผลอนุมัติต้องตรวจหลักฐานก่อนมีผลหักสิทธิ/ประกอบ ฉ.11 โควตาที่ขาดไม่แทนด้วยศูนย์
8. ส่งสถานะ cancelled เป็นรายการยกเลิกอย่างชัดเจน ไม่ถือว่ารายการที่ไม่อยู่ในไฟล์ต้องถูกลบ ประวัติต้นทางแยกจากประวัติการนำเข้าปลายทาง
9. ทดสอบ local → cloud, cloud → local, ไฟล์ซ้ำ, ข้ามหน่วย, บุคลากรชื่อซ้ำ, แก้ทั้งสองฝั่ง, วันลาซ้อน, ทะเบียนไม่ครบ, ไฟล์เสียหาย และ rollback การนำเข้าให้ผ่านก่อนเปิดใช้งาน

แต่ละฝั่งทำงานได้แยกจากกัน ไม่มี background sync, realtime replication หรืองานส่งข้อมูลอัตโนมัติ การนำเข้าแต่ละครั้งต้องเป็นการเลือกส่งและรับที่ผู้ใช้สั่งเอง

## หลักฐานและข้อจำกัด

ทดสอบโค้ด การนับวัน สิทธิ์ใน PostgreSQL ด้วย transaction ที่ rollback และหน้าจอด้วยข้อมูลจำลอง แบบพิมพ์ตรวจ PDF/ภาพแล้ว แต่ยังต้องทดลองกับเครื่องพิมพ์จริง การซ้อมกู้คืนข้อมูลใช้ตารางชั่วคราว ไม่รวม Auth/Storage/schema recovery ทั้งระบบ
