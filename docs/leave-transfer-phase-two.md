# รับส่งทะเบียนลา cloud ↔ local รุ่น 1.76

ระบบรับส่งด้วยแฟ้มที่ผู้ใช้สั่งเอง ไม่มีการซิงค์หรือส่งข้อมูลเบื้องหลัง ไม่ต้องใช้คุณสมบัติ Supabase Pro ใช้ตารางและสิทธิ์เดิมสำหรับทะเบียนลา เพิ่มเพียงทะเบียนชุดติดตั้งกับประวัติรับข้อมูลใน cloud

## วิธีใช้งาน

1. Cloud: เปิดหน้าสำหรับเจ้าหน้าที่ เลือกบุคลากรและปีงบประมาณ แล้วกด **ส่งออก / นำเข้า** ในส่วนการลา
2. Local: เปิดเมนู **รับส่งทะเบียนลา / ปฏิทินรายหน่วย** เลือกบุคลากรและปีเดียวกัน ชุดนี้ต้องติดตั้งและกำหนดหน่วยโดยผู้เขียนก่อน
3. ADMIN เชื่อม UUID บุคลากร cloud กับบุคลากร local ครั้งแรก ตรวจตัวบุคคลและหน่วยจริง ไม่มีการจับคู่ด้วยชื่อหรืออีเมลอัตโนมัติ UUID แสดงบนหน้ารับส่งของ cloud และห้ามเปลี่ยน UUID ของคนที่เชื่อมแล้วผ่านหน้ารับส่ง
4. ส่งออก: ตั้งรหัสผ่านแฟ้มอย่างน้อย 12 ตัวอักษรและยืนยัน จะได้แฟ้ม `.kelang` เก็บรหัสผ่านแยกจากแฟ้ม ถ้าลืมรหัสให้ส่งออกใหม่ Local ต้องเปิดผ่าน localhost หรือ HTTPS เพื่อใช้การเข้ารหัสของเบราว์เซอร์
5. รับเข้า: เลือกแฟ้ม ใส่รหัสผ่าน ยืนยันตัวบุคคล/หน่วย/ปี และกดตรวจไฟล์ ยังไม่เขียนทะเบียนในขั้นนี้
6. หน้าตรวจแสดงเพิ่ม / ข้อมูลต่างกัน / เหมือนเดิม / ขัดแย้ง เปิดดูข้อมูลก่อน–หลัง รายการต่างกันไม่ได้เลือกให้อัตโนมัติ เลือกเฉพาะรายการที่ตรวจแล้วและยืนยันก่อนรับ
7. หลังรับ ตรวจปฏิทินตามประกาศของหน่วยและยืนยันแต่ละเดือน ใบลาที่รับใหม่จะรอตรวจผลตามเอกสารที่ลงนามจริง ไม่ใช้สถานะอนุมัติจากต้นทางแทนการตรวจหลักฐาน
8. ดูข้อมูลต้นทางใน **ประวัติรับข้อมูลล่าสุด → ดูข้อมูลต้นทางเพื่อเทียบเอกสาร** แยกผู้บันทึกการรับแฟ้มออกจากผู้ลงนามที่ต้นทางระบุ ข้อมูลต้นทางไม่ใช่การรับรองว่าลายเซ็น/เอกสารนั้นถูกต้อง

ส่งออกครั้งละหนึ่งบุคลากรและหนึ่งปี พร้อมปฏิทินรายหน่วยของปีนั้น ทะเบียนลาและสิทธิที่มี ไม่ส่งบัญชี รหัสผ่าน session/token กุญแจระบบ เลขบัตรประชาชน หรือข้อมูลผู้ป่วย ขนาดข้อมูลก่อนเข้ารหัสไม่เกิน 2 MB / 1,012 รายการ; แฟ้มเข้ารหัสมีขนาดใหญ่ขึ้นจาก Base64

## กติกาป้องกันบันทึกทับ

- Cloud ตรวจสิทธิ์ ADMIN/STAFF ตามหน่วยจากฐานข้อมูลทุกครั้ง ส่วน local ตรวจบัญชีและหน่วยที่ผู้เขียนอนุญาต ไม่เชื่อสิทธิ์ที่ผู้ส่งเขียนมาในไฟล์
- ชุด local ต้องมี installation_id ถาวรและผ่านทะเบียนชุดติดตั้งใน cloud โดย ADMIN ชุด local นี้รับจาก cloud ที่กำหนดไว้เท่านั้น
- ไฟล์ใช้ AES-256-GCM, PBKDF2-SHA256 310,000 รอบ, salt/IV ใหม่ต่อแฟ้ม และตรวจ SHA-256/จำนวนรายการของข้อมูลภายใน รหัสผ่านไม่ส่งไป cloud หรือ API local
- UUID ใช้เป็นรหัสแลกเปลี่ยน ทะเบียน mapping ของ local เก็บรหัส AUTO_INCREMENT ภายในแยกกัน ปฏิทินจับรายการเดิมตามหน่วย+เดือน สิทธิใช้บุคลากร+ปี
- ฝั่งรับคำนวณ token จากข้อมูลปลายทาง เมื่อกดรับต้องตรวจใหม่และตรงกับหน้าที่ตรวจไว้ หากมีผู้แก้ก่อน จะหยุดให้เทียบใหม่ ไม่ใช้เวลาล่าสุดเป็นคำสั่งทับ
- บันทึกข้อมูลก่อนแก้และข้อมูลต้นทางใน transaction เดียวกับรายการที่เลือก ข้อผิดพลาดกลางทางย้อนกลับทั้งรายการ ไม่เหลือทะเบียน/ประวัติรับเข้าบางส่วน
- package_id เดิมพร้อมข้อมูลเดิมไม่รับซ้ำ หาก package_id เดิมแต่เนื้อหาต่างกันจะปฏิเสธ หากเลือกรับเพียงบางรายการ แฟ้มทั้งชุดจะถือว่ารับแล้ว การรับรายการที่ข้ามต้องส่งออกเป็นแฟ้มใหม่
- ไม่มีรายการในแฟ้มไม่หมายถึงลบปลายทาง สิทธิที่เลือกแทนที่เป็นทั้งชุดของบุคลากร/ปีนั้น ช่องที่ไม่มีหมายถึงยังไม่กำหนด ไม่เติมศูนย์
- รายการปิดแล้วไม่เขียนทับ ข้อมูลวันลาซ้อนแสดงขัดแย้ง รายการประวัติที่ยกเลิก/ไม่อนุมัติจากต้นทางซึ่งยังไม่มีปลายทางเก็บไว้ในแฟ้ม/หลักฐานต้นทาง ไม่สร้างคำขอรอผลใหม่ให้ ถ้ามีคำขอรอผลรหัสเดิมและเนื้อหาหลักตรงกัน จึงรับสถานะยกเลิก/ไม่อนุมัติได้หลังเลือกตรวจ
- ข้อความที่เกินขนาดคอลัมน์ local จะปฏิเสธ ไม่ตัดข้อความทิ้ง ช่องพักผ่อนที่ local เดิมไม่มีคอลัมน์เก็บใน metadata เพื่อส่งกลับได้

## ปฏิทิน local และเอกสารราชการ

ปฏิทิน local เดิมเป็นปฏิทินกลางทุกหน่วย จึงเพิ่มตารางปฏิทินรายหน่วยแบบรายเดือน เก็บเฉพาะวันที่ต่างจากเสาร์–อาทิตย์ การรับแฟ้มไม่แก้ปฏิทินกลาง ถ้ายังไม่มีเดือนรายหน่วยจะใช้ปฏิทินเดิม เมื่อรับแล้วการนับวันลา ใบรับรองรายเดือน และรายงานรายหน่วยจะใช้เดือนของหน่วยนั้น

แก้วันหยุดจะกลับเป็นร่าง ต้องตรวจและยืนยันอีกครั้ง ใบรับรอง local เปิดแบบพิมพ์เมื่อปฏิทินยืนยัน ไม่มีใบลารอตรวจผลหรือรายการไปราชการ/หยุดอื่นที่ต้องพิจารณาวันทำงานเอง และ STAFF ยืนยันว่าทะเบียนครบ ข้อความและการจัดหน้าแบบราชการเดิมคงเดิม การกดบันทึก/รับแฟ้ม/ยืนยันทะเบียนไม่ใช่การลงนามราชการ

## ขนาดข้อมูลและการสำรอง

ประวัติรับข้อมูล cloud จำกัดเนื้อหาข้อมูลก่อนแก้+ต้นทางที่ **3 MB ต่อหน่วย** รวม 8 หน่วยสูงสุดประมาณ 24 MB ของเนื้อหา (ยังมี overhead/index ของฐานข้อมูล) เมื่อถึงขนาดจะหยุดรับและแจ้ง ADMIN ให้เก็บสำรองเข้ารหัสก่อนจัดเก็บประวัติ Local จำกัด 25 MB ต่อหน่วย ไม่มีการลบประวัติอัตโนมัติ

ระบบมีข้อมูลก่อนแก้สำหรับตรวจคืนค่า แต่ยังไม่มีปุ่มกู้คืนหรือปุ่มย้ายประวัติออกเพื่อลดพื้นที่ ปัจจุบันผู้ดูแลต้องดำเนินการตามข้อมูลสำรองและตรวจสิทธิ์เอง การกู้คืนทั้ง Auth/Storage/schema ไม่อยู่ในขอบเขตนี้

## ติดตั้งชุด local โดยผู้เขียน

เก็บ source ใน `local/leave-transfer` ของ repository นี้ และเรียกจาก CLI:

```text
php local/leave-transfer/install.php ABSOLUTE_COMPENSATION_DIR FACILITY_CODE
```

ตัวติดตั้งปฏิเสธการเรียกผ่านเว็บ สร้าง installation_id ครั้งแรกและคงเดิมเมื่ออัปเดต ไม่เปลี่ยนหน่วยเดิมอัตโนมัติ ต้องตรวจว่าตำแหน่ง `private/leave-transfer` ที่สร้างอยู่ภายนอก document root ของเครื่องปลายทางก่อนจัดส่ง ตัวติดตั้งสำรองไฟล์ที่เชื่อมระบบไว้ในพื้นที่ private และหยุดเมื่อพบโครงสร้างไฟล์หลักที่ไม่รู้จัก ควรสำรองฐานข้อมูลทั้งชุดก่อนติดตั้ง/อัปเดตด้วย

ชุดปัจจุบันติดตั้งนำร่องโทกหัวช้าง 06116 และเชื่อมอภิวัฒน์ไว้แล้ว ยังไม่ย้ายประวัติวันลาจริง หน่วยอื่นต้องจัดชุดติดตั้งและลงทะเบียน/เชื่อมบุคลากรตามสิทธิ์ก่อน

## ผลทดสอบและงานถัดไป

ผ่าน JS 142 tests, PostgreSQL 21 checks แบบ rollback, local 25 checks ในฐานทดสอบแยกที่ลบหลังทดสอบ, browser 8 flows และตรวจแฟ้มเข้ารหัสสองทิศทางกับข้อมูลปฏิทินจริงแบบ preview ไม่เขียนทะเบียน

ยังต้องทดลองโดยเจ้าหน้าที่ด้วยบัญชีจริงและเอกสารลงนามจริงของเดือนตุลาคม 2569 จากนั้นจึงขยายชุดติดตั้งรายหน่วย เฟสถัดไปควรทำปุ่มสำรอง/ย้ายประวัติเก่าโดยคงรหัสกันแฟ้มซ้ำ และหน้ากู้คืนแบบตรวจรายการก่อนทำจริง รวมถึงเลือกเดือน/ส่งหลายคนเมื่อมีผลทดลองยืนยันแล้ว
