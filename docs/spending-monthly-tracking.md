# ติดตามแผนใช้เงินรายเดือน — 1.78

หน้า `#spending` เข้าได้จากเมนูติดตามแผนใช้เงินและหน้าเจ้าหน้าที่ ปีเริ่มต้น 2570 (ต.ค. 2569–ก.ย. 2570) แยกตัวกรองจากปีของ HDC

## การทำงาน

- STAFF เห็นและบันทึกเฉพาะหน่วยที่ได้รับมอบหมาย ADMIN เลือกครบ 8 หน่วย ผู้ใช้ทั่วไปและผู้ไม่เข้าสู่ระบบอ่านรายละเอียดไม่ได้
- หนึ่งรายงานต่อหน่วย/ปี/เดือน เก็บทุกรายการในคำขอเดียว ไม่มีรายการจ่ายรายวัน
- บันทึกร่างได้เมื่อกรอกไม่ครบ ช่องว่างกับศูนย์แยกกัน ยืนยันได้เมื่อกรอกครบทุกช่องรับยอด
- ยืนยันแล้วแก้ไขไม่ได้ ADMIN ต้องเปิดเดือนพร้อมเหตุผลก่อน
- ลบร่างแบบกู้คืน เก็บข้อมูลเดิมและเหตุผล ไม่ให้ hard delete
- ส่ง revision เดิมเป็นเงื่อนไข UPDATE ป้องกันบันทึกทับผู้แก้ไขอีกคน
- ยอดสะสม/คงเหลือใช้เฉพาะเดือนที่ยืนยันแล้ว เรียง ต.ค.–ก.ย. หน้าภาพรวมปีแสดง — เมื่อยังไม่มีรายงาน

## Cloud

เพิ่มตารางเดียว `public.hp_spending_reports` ใน project `txjuiaiwffsxfcrxpkvd`:

- period 0: แผนรายละเอียดปี 2570 ของหน่วย พร้อม source filename/sheet/hash/cell values/formulas
- period 1–12: ยอดจริงใน payload.amounts keyed by source row ID พร้อมหมายเหตุ อ้าง plan id/revision
- UNIQUE(facility_code,fiscal_year,period), RLS ผ่าน helper STAFF/ADMIN และ session policy เดิม
- Trigger ตรวจ identity, revision, รายการที่มีจริง, ตัวเลขไม่ติดลบ/ไม่เกินสองตำแหน่ง, ความครบถ้วนก่อนยืนยัน, ล็อกเดือนยืนยัน และเหตุผลลบ
- Audit ใช้ `hp_audit_logs` เดิม ไม่เพิ่มตารางประวัติ
- เมื่อมีรายงานแล้วไม่ให้เขียนทับแผนต้นฉบับ การเปลี่ยนแผนระหว่างปีต้องพัฒนาขั้นตอน revision ของแผนแยกต่างหาก
- ข้อมูลรายเดือนนี้ยังแยกจาก `hp_finance_monthly` ปี 2569 และหน้าการเงินสาธารณะ ไม่ส่งยอดร่างไปเป็นยอดเผยแพร่

DDL ที่ใช้งานอยู่: `supabase/migrations/20261016032534_spending_monthly_tracking.sql` (รวมการแก้ guard หลังทดสอบ) Cloud มี follow-up migrations `spending_plan_read_guard_fix` และ `spending_scope_guard` ซึ่งรวมอยู่ใน local DDL ฉบับนี้แล้ว ห้ามรัน CREATE TABLE ซ้ำบน project ที่ติดตั้งแล้ว

## แผนต้นทาง

อ่าน .xlsx ทั้ง 8 ไฟล์จากโฟลเดอร์แผนเงินแก้ไข2_70 ด้วย `scripts/import-spending-plan.py` โดยไม่เปลี่ยนไฟล์ต้นฉบับ ผลที่นำเข้ามี 88 หมวดใหญ่ และ 452 แถวต้นทาง (รวมหัวข้อและรายการย่อย) ต้องไม่ใช้ยอดรวมแล้วบวกหัวข้อกับรายการย่อยซ้ำ

บางแถวมีวงเงินอิสระแม้เลขรายการคล้ายรายการลูก เช่น วัสดุสำนักงาน 2.7 และรายการซื้อ 2.7.1 จึงรักษาวงเงินแยกตามสูตร/ยอดต้นฉบับ บางรายการบุคลากรไม่มีเลขรายการ จัด key ภายในโดยคงข้อความเดิม

บางหน่วยระบุวงเงินรวมของหัวข้อ แต่ไม่แจกวงเงินให้ลูกทุกรายการ ช่องเหล่านั้นแสดง — และยังกรอกจ่ายจริงได้ ส่วนยอดภาพรวมใช้แผนสรุปของหน่วย ข้อสังเกตแสดงในหน้าจอ:

- บ้านฟ่อน ศรีหมวดเกล้า และแม่กืย มีวงเงินบางหัวข้อที่ไม่ได้แจกแจงให้ทุกรายการลูก
- กล้วยม่วง หมวด 5 ผลรวมรายการย่อยมากกว่าแผนสรุป 1,800 บาท เก็บทั้งสองค่าตามต้นฉบับ ไม่ปรับยอดเอง
- แม่กืยมีสูตร #REF! บางเซลล์ต้นทาง เก็บสูตรไว้ และใช้ค่าจาก summary/สูตรที่อ่านยืนยันได้เท่านั้น

ผลนำเข้าและ source snapshots อยู่ `backups/spending/` ซึ่งถูก gitignore ไม่รวมใน public build
