# จัดการ KPI — Ver.1.5

เข้าสู่ระบบด้วยบัญชี ADMIN แล้วเปิดเมนู **จัดการ KPI (ADMIN)** หรือเข้าจากลิงก์ในหน้า **จัดการข้อมูล**

1. เลือกปีงบประมาณและช่วงเวลา
2. ดูสถานะข้อมูล จำนวนหน่วยที่มีค่า วันข้อมูล และผลการตรวจ API สดล่าสุด
3. กด **ตรวจ API สด** รายตัว หรือ **ตรวจ API สดทุก KPI ทีละรายการ** (ห่าง 3 วินาที) มีปุ่มหยุดหลังคำขอปัจจุบัน
4. ติ๊ก **อนุญาตให้แสดง** เพื่อเปิด หรือเอาติ๊กออกเพื่อพักการแสดงในปีนั้น ปุ่ม **อัตโนมัติ** คืนค่าเริ่มต้น

การเปิดอนุญาตไม่ได้ทำให้การ์ดว่างปรากฏ: ต้องมีค่าที่คำนวณได้สำหรับช่วงเวลา/หน่วยที่เลือก ค่า 0 จริงนับเป็นข้อมูล เมื่อข้อมูลใหม่เข้าจะกลับมาแสดงได้ หาก ADMIN ซ่อนด้วยตนเองจะซ่อนต่อไปจนเปิดเอง

API ขัดข้องถูกแยกจากไม่พบข้อมูล หากมีข้อมูลล่าสุดที่ใช้ได้ยังแสดงพร้อมคำอธิบาย หากไม่มีข้อมูลให้ใช้จะพักผลว่างและแจ้งปัญหาในคุณภาพข้อมูล/หน้าจัดการ ไม่สรุปว่าไม่มีข้อมูลจริงเพราะ HTTP 429

การซ่อนมีผลต่อภาพรวม การ์ด KPI, OPD summary, ตัวเลือก AREA/SERVICE, Ranking/Heatmap/Trend/Compare และ HDC ในหน้าหน่วยบริการ ผู้ดูแลและหน้า Quality ยังคงเห็นทุก KPI เพื่อแก้ปัญหา

การตั้งค่าเก็บใน `hp_settings` หมวด `kpi_publication`, key `kpi_publication:{ปี}:{KPI}` มี mode auto/show/hide และ metadata ผลตรวจล่าสุด ไม่เก็บชุดข้อมูล HDC ใน Supabase ไม่มีตารางใหม่ ใช้ RLS ADMIN-only เดิม และเพิ่ม audit trigger เพื่อบันทึกการเปลี่ยนแปลง settings

หากอ่านการตั้งค่ากลางไม่สำเร็จ ระบบพักการแสดง KPI และแจ้งข้อผิดพลาด แทนการเปิดรายการที่ผู้ดูแลซ่อนไว้โดยไม่ทราบค่าเดิม

ตรวจสอบ: unit/integration 24 tests; browser 31 จุด; ชุดทดสอบ UI จำลอง ADMIN สำหรับเปิด/ซ่อน/refresh/ปีว่าง/ปุ่มตรวจสด; SQL บนฐานข้อมูลจริงทดสอบ ADMIN เขียน + audit, STAFF ห้ามเขียน, Public อ่านแต่ห้ามเขียน แล้ว rollback ไม่ทิ้งข้อมูลทดสอบ การเข้าเบราว์เซอร์ด้วยรหัสผ่าน ADMIN จริงไม่ได้ทดสอบเพราะไม่ได้รับรหัสผ่าน
