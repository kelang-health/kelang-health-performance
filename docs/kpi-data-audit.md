# รายงานตรวจ KPI ที่ไม่มีข้อมูล

ตรวจวันที่ 6 ตุลาคม 2569 ครอบคลุม 26 KPI × 3 ปี = 78 ชุดข้อมูล แหล่งข้อมูล: HDC Open Data MOPH และ snapshot ที่เผยแพร่จริง ตรวจ API สดเพิ่มสำหรับรายการที่ว่างปี 2570 ทั้ง 26 ตัว และ SERVICE ปี 2569 อีก 2 ตัว ทุกคำขอที่ตรวจสดสำเร็จ ไม่มี HTTP 429 ในรอบนี้

## ผลสรุป

- ปี 2568: ทุก KPI มีค่ารายปีอย่างน้อยหนึ่งหน่วย (26/26) ข้อมูลส่วนนี้ตรวจจากชุดข้อมูลจริงที่เผยแพร่ ไม่ได้เรียก API สดซ้ำครบทุกตัว
- ปี 2569: AREA 24 ตัวครบ 7/7 หน่วย; SERVICE 2 ตัวมี 7/8 หน่วย ทุก KPI มีค่ารายปี จึงไม่มี KPI ที่ควรลบออกทั้งหมด
- ปี 2570: ตรวจ API สดครบ 26 ตัว ไม่พบแถวของหน่วยบริการในขอบเขตเรา ยืนยันว่าไม่มีข้อมูลสำหรับปีนี้ ณ เวลาตรวจ ยังสรุปไม่ได้ว่า KPI นี้จะไม่มีข้อมูลตลอดไป
- OPD/ทันตกรรม ปี 2569: ตรวจ API สด ไม่พบแถวของรหัส 45030 ศบส.เขลางค์นคร ส่วนอีก 7 แห่งมีข้อมูล จึงควรซ่อนค่าที่ว่างเฉพาะหน่วยนี้หรือแจ้งไม่มีข้อมูล ไม่ตัด KPI ทั้งตัว

## ข้อเสนอสำหรับการปรับเว็บ

1. ซ่อนผล KPI ที่ยืนยันว่าไม่มีข้อมูล เฉพาะปี/ช่วงเวลา/หน่วยที่เลือก และแสดงจำนวนรายการที่ซ่อนไว้ เพื่อไม่ให้ผู้บริหารเข้าใจว่าเป็นผลศูนย์
2. ปี 2570 แสดงข้อความรวม “ยังไม่มีข้อมูล HDC ปี 2570 สำหรับหน่วยบริการในระบบ” แทนการ์ดว่าง 26 ตัว และยังคงเลือกปี 2568/2569 ได้
3. เลือกเฉพาะ KPI ที่มีรายเดือนในโหมดรายเดือน และเฉพาะ KPI ที่มีข้อมูลช่วงเวลาที่เลือกในโหมดไตรมาส เก็บ KPI รายปีไว้เมื่อเลือกสะสมรายปี
4. ไม่ซ่อนเพราะ HTTP 429/CORS/timeout: ใช้ข้อมูลจริงล่าสุดพร้อมสถานะ API ขัดข้อง; ถ้าไม่มี cache ให้แจ้งว่าตรวจไม่ได้
5. ค่า 0 ที่ต้นทางส่งจริงยังแสดง; ไม่มีตัวหารหรือเป้าหมายไม่ใช่เหตุให้ลบ KPI โดยอัตโนมัติ; รหัส 45030 ใน AREA คือ N/A ตาม scope ไม่ใช่ข้อมูลหาย
6. ไม่ลบ KPI ออกจาก master ถาวร เพราะเมื่อ HDC ส่งข้อมูลใหม่ระบบต้องแสดงได้อีก

รายงานนี้เป็นการตรวจและข้อเสนอ ยังไม่ได้เปลี่ยนกติกาซ่อน KPI บน production และไม่ได้แก้ข้อมูล HDC ต้นทาง
